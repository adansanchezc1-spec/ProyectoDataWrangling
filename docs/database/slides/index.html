DECISIONES CRÍTICAS DE DISEÑO DE SOFTWARE

Proceso de Abstracción vs. Antipatrón "God Table"

❌ El Antipatrón: La Tabla Plana Única (God Table) 25+ CAMPOS ACOPLADOS
✕
Anomalías de Actualización Masivas: Nombres de barrios y localidades duplicados millones de veces. Modificar una nomenclatura exige bloqueos destructivos de tabla.
✕
Destrucción del Linaje Crudo (Violación ISO 8000): Sobrescribir datos crudos anula la capacidad de auditar qué entregó la fuente original ante inconsistencias legales o analíticas.
✕
Violación del Principio SOLID SRP: Acoplamiento en una sola estructura de metadatos de archivo, datos del bien raíz, auditoría de compuertas y variables de ML.
✕
Incompatibilidad Multiusuario / Batch: Imposible orquestar cargas concurrentes de múltiples datasets sin colisión de identificadores.
✅ Solución: Cuadrantes Semánticos DAMA BCNF & INMUTABILIDAD
✓
Inmutabilidad Estricta en Staging: stg_inmuebles_raw es una estructura append-only; el dato original jamás se sobrescribe.
✓
Normalización Territorial 1NF→3NF: Catálogos discretos de localidades y barrios con centroides calibrados para rechazar ubicaciones ajenas a Bogotá.
✓
Aislamiento de Feature Store: Las variables derivadas para modelos predictivos residen en fct_features_analiticas, respetando SRP.
✓
Auditoría Granular de Compuertas BPMN: Registro forense de rechazos sin degradar las tablas maestras consolidadas.

RIGOR MATEMÁTICO RELACIONAL

Demostración Matemática: 1NF → 2NF → 3NF → BCNF

Dependencias Funcionales Canónicas del Dominio (F):
DF₁: {id_maestro} → {direccion_norm, tamano_m2, habitaciones, banos, estrato, precio, id_barrio}
DF₂: {direccion_norm, tamano_m2, id_barrio} → {id_maestro} [Clave Candidata / Hash Unicidad RB-003]
DF₃: {id_barrio} → {nombre_barrio, estrato_moda, latitud, longitud, id_localidad}
DF₄: {id_localidad} → {codigo_dane, nombre_localidad, zona_bogota}
1NF
Atomicidad Escalar

Descomposición de la cadena ubicación en componentes escalares indivisibles: localidad, barrio y dirección normalizada.

2NF
Cero Dep. Parciales

Uso de claves primarias subrogadas sintéticas (INT / BIGINT / UUIDv4). Todo atributo no-primo depende de toda la clave.

3NF
Cero Transitividad

Eliminación de la transitividad territorial: el inmueble referencia a barrio, y el barrio a su localidad.

BCNF
Superclave Estricta

Para toda DF X → Y en el esquema, X es Superclave. Descomposición con reunión sin pérdida garantizada.

SWEBOK v4 SOFTWARE DESIGN & SEGURIDAD

Persistencia Desacoplada (SOLID DIP) & Seguridad

🧩 Repository Pattern (SOLID-DIP) ARQUITECTURA
✓
Inversión de Dependencias: El dominio de negocio depende de la abstracción IDataRepository, no del motor concreto.
✓
Adaptador MySQL: Implementación aislada en infrastructure/repositories/mysql_repository.py con pool de conexiones.
✓
Alta Testabilidad: Permite probar la lógica de las compuertas BPMN con dobles de prueba (Mocks) sin requerir base de datos activa.
🛡️ Seguridad & Protección de Datos PoLP / ISO 8000
✓
Principio de Mínimo Privilegio (PoLP): El usuario de aplicación solo tiene privilegios DML (SELECT, INSERT, UPDATE, DELETE), sin facultades DDL ni de administración.
✓
Hashing Criptográfico SHA-256: Verificación de integridad de archivos de entrada (ISO 8000) y clave de deduplicación.
✓
Blindaje contra SQL Injection: Todas las transacciones se ejecutan mediante sentencias preparadas y parámetros tipados.
